Connect GitLab

A one-time setup per project, done in a couple of minutes. You'll create one access token for this portal in the project. Afterwards, the portal can mint project access tokens there with a single click — each one a bot member of that project and nothing else.

1

Say which GitLab and which project

The URL is your GitLab's address — keep https://gitlab.com unless you run your own. The project is the numeric Project ID from the project's overview page (under its name), or the full path like my-group/my-app.

2

Create the portal's own access token in that project

  1. In the project, open Settings → Access tokens (you need at least the Maintainer role to see it).
  2. Press Add new token, name it api-key-portal.
  3. Pick an expiry (GitLab requires one — put a reminder key in this portal!).
  4. Role Maintainer, scope api, then create it.
  5. Copy the token immediately — GitLab shows it only once — and paste it below.

A project access token can only act inside that one project, so this is the least-privileged option: the portal can mint tokens there and touch nothing else on your GitLab.

3

Name it and connect

This name shows up in the provider dropdown on the Add key screen, and as the service name on keys created through it.

The portal verifies the connection against GitLab before anything is saved, so typos surface right here.
