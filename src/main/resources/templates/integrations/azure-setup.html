Connect Microsoft Azure AD

A one-time setup, done in about five minutes. You'll register this portal in your Azure tenant and paste three values back here as you go. Afterwards, the portal can create clients and client secrets in Azure for you with a single click.

1

Register an application for this portal

Azure needs to know this portal before the portal can act in your tenant. Sign in as an administrator of the tenant, then:

  1. Open the registration form with the button below.
  2. Name it API Key Portal (any name works).
  3. Leave the account type on Accounts in this organizational directory only (single tenant).
  4. Skip the redirect URI and press Register.
Open "Register an application" in the Azure portal
2

Copy the two IDs from the Overview page

After registering, Azure shows the app's Overview page. Copy both IDs from the top of that page into the fields below.

3

Allow the portal to create app registrations

Still on your new app registration, grant it one Microsoft Graph permission:

  1. In the left menu choose API permissions.
  2. Press Add a permission → Microsoft Graph → Application permissions.
  3. Search for and tick Application.ReadWrite.OwnedBy, then press Add permissions.
  4. Press Grant admin consent for <your tenant> and confirm. The permission's status should show a green check mark.

This is the least-privileged option: the portal can only manage app registrations it created itself, never anything else in your tenant.

4

Create a client secret for the portal

  1. In the left menu choose Certificates & secrets.
  2. Press New client secret, describe it (e.g. API Key Portal), pick an expiry and press Add.
  3. Copy the Value column immediately — Azure shows it only once — and paste it below.

Stored encrypted (AES-256-GCM) and never shown again in this portal either. When it expires, create a new secret in Azure and reconnect here.

5

Name it and connect

This name shows up in the provider dropdown on the Add key screen, and as the service name on keys created through it.

The portal verifies the connection against Azure before anything is saved, so typos surface right here.
